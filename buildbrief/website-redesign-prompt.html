PRACTICAL PROMPT GUIDE

Give an AI coding tool a redesign brief, not just “make it look better.”

A redesign can look polished in a screenshot and still break navigation, forms, mobile layouts, or existing behavior. This guide helps you describe the visual direction while protecting the parts of the website that already work.

Define the redesign before the code changes

Separate the goal, the existing baseline, the desired direction, and the checks for success. That gives an AI coding assistant fewer gaps to fill with guesses.

01

What already works

Identify pages, flows, brand elements, and components that must stay. Existing behavior is a requirement, not an optional detail.

02

Visual direction

Name the hierarchy, spacing, typography, color roles, and reference elements you want. Explain what a reference illustrates instead of asking for a blind copy.

03

Pages in scope

List the exact page, section, or shared component to change. Avoid “redesign the entire site” when one page is the real goal.

04

Responsive behavior

State relevant viewport widths and how navigation, cards, forms, and sidebars should adapt.

05

Accessibility and interaction

Preserve keyboard focus, readable contrast, visible states, labels, and useful feedback for buttons and forms.

06

Visual verification

Ask to review the actual page at representative sizes, look for overflow and regressions, and report what was checked.

A vague design request vs. a buildable brief

Specific steps make the result easier to reproduce and verify.

Too vague

“Make my website modern and beautiful.”

Better

“Improve the pricing page only. Keep the existing plans, URLs, checkout buttons, and brand colors. Align plan cards, improve heading hierarchy, make the comparison readable at 375px and 1440px widths, and check for horizontal overflow and broken interactions.”

Copyable website-redesign prompt

Improve the existing website UI without breaking its behavior.

GOAL:
[Describe the audience, the page or component, and the visual problem to solve.]

KEEP:
[List existing flows, content, branding, routes, components, and data that must remain.]

CHANGE:
[Describe hierarchy, layout, spacing, typography, color roles, imagery, and interactions.]

SCOPE:
[Name the exact pages and components in scope. State what is out of scope.]

RESPONSIVE REQUIREMENTS:
[Name relevant viewport sizes and how the layout should adapt.]

CONSTRAINTS:
- Inspect the current implementation and reuse existing design tokens/components when appropriate.
- Preserve working links, forms, validation, navigation, and application logic.
- Do not replace functional content with a static image or screenshot.
- Do not introduce a new UI library, dependency, or external asset without a clear need.
- Keep focus states, semantic labels, and readable contrast.

ACCEPTANCE CHECKS:
- Check at a narrow mobile width and a desktop width.
- Look for clipped text, overlapping components, and horizontal scrolling.
- Test the main interactions and navigation.
- Summarize changed files and checks that could not be performed.

Design-review checklist

  • Did you say exactly what should stay unchanged?
  • Is the desired visual direction concrete enough to review?
  • Have you named the pages and components in scope?
  • Do mobile and desktop have explicit expectations?
  • Have you asked to verify interactions, overflow, and focus states?

Website-redesign prompt questions

Can I just send a screenshot?

A screenshot helps communicate layout and style, but also describe behavior, what should stay, and page states that are not visible in the image.

Should I ask for a full redesign in one prompt?

Start with one page or a shared component. A smaller scope helps preserve behavior and makes the result easier to verify.

How do I prevent a screenshot-like implementation?

State that the result must remain real HTML/CSS and functional components. Ask the assistant to test actual links, forms, and responsive layouts.
